# 문제 정의서 · 거래명세서를 장부에 옮겨 적는 일

작성일: 2026-11-18
이 문서가 PoC의 기준입니다. 세부는 [01_업무정의.md](01_업무정의.md)(업무 유형, 적용하지 않을 조건), [02_성공기준.md](02_성공기준.md)(기준 6개, 모델 실행 전에 고정)에 있습니다.

> **한 줄 요약**: 거래처가 보낸 거래명세서(스캔 PDF)를 사람이 장부에 옮겨 적는 일의 앞단에 AI(글자 인식 + 규칙)를 넣어 행 초안을 만들고, 사람은 **"확인 필요"로 표시된 값만** 확인합니다.

## 1. 도메인 설명
- **무엇**: 식당(이자카야·꼬치 전문점) 운영. 그중 **거래처(식자재·주류 납품처)에서 오는 거래명세서를 확인하고 장부(엑셀)에 입력하는 업무**입니다.
- **누가 하나**: 사장과 직원이 합니다(인터뷰 답). 언제 어떤 순서로 처리하는지는 확인하지 못했습니다.
- **자료의 모양**: 종이, PDF, 팩스로 오고, 거래처마다 양식이 다릅니다. 담는 정보는 거래처, 날짜, 품목, 수량, 단가, 합계입니다.
- **왜 이 지점인가**: 식당 운영에서 AI를 넣을 수 있는 후보를 셋 놓고 비교했습니다.

| 후보 | 선택 | 이유 |
|---|---|---|
| 거래명세서를 장부에 옮겨 적기 | **선택** | 정답이 서류에 있어 판정 기록이 없어도 채점할 수 있음. 금액·수량 오류가 정산에 바로 영향을 줌. 단가·거래처명이 있어 외부로 못 보내는 조건이 실제로 걸림 |
| 고객 문의(영업시간, 예약, 알레르기) 답변 초안 | 제외 | 답변 문장을 숫자로 채점하기 어렵고, 알레르기 답변은 틀리면 되돌릴 수 없음 |
| 카톡 발주 문자를 품목·수량 표로 정리 | 제외 | 거래처마다 말투가 달라 기준을 세울 자료가 부족함 |

## 2. 현재의 문제
**지금은 어떻게 하나**: 사장이나 직원이 명세서를 보면서 품목, 수량, 단가, 합계를 장부에 직접 입력합니다. 거래처 문의 중에서 가장 손이 많이 가는 일로 꼽은 것이 **명세서를 옮겨 적는 일**과 **지난 단가·납품일을 찾아보는 일**이었습니다. (이번 PoC는 앞의 것만 다룹니다. 문의 건수는 하루 10~30건으로 고객과 거래처 문의를 합친 값이고, 명세서만의 건수는 재지 않았습니다.)

**어떤 점이 번거롭고 비효율적인가**
1. **옮겨 적는 데 시간이 듭니다.** 거래처 쪽에서 손이 가장 많이 가는 일로 꼽으셨습니다. 장당 걸리는 시간은 **재지 않았습니다**.
2. **틀려도 알아채기 어렵습니다.** 옮겨 적은 값이 그럴듯하면 검산 없이 넘어가기 쉽다는 것은 이 유형의 일(입력과 전사)의 일반적인 위험이고, 이 가게에서 실제로 겪은 오류는 확인하지 못했습니다. 다만 금액·수량 오류를 가장 걱정한다고 답하셨습니다. 틀리면 정산과 발주에 그대로 이어집니다.
3. **지난 처리 기록이 거의 남아 있지 않습니다**(인터뷰 답. 문의 채널은 전화, 카톡·문자, 이메일·팩스·종이). 그래서 채점할 자료도 지금 만들어야 합니다.

**지금 방식의 수준(기준선)**: 장당 입력 시간과 오류율을 **측정하지 않았습니다.** PoC의 가장 큰 빈 곳입니다.

## 3. 개선 가설
> **가설**: 명세서 PDF를 글자 인식(OCR) + 규칙으로 읽어 행 초안을 만들고 신뢰도가 낮거나 계산이 맞지 않는 값에 "확인 필요"를 붙이면, ① 사람은 확인 필요 값만 보면 되어 입력 시간이 줄고, ② 틀린 값이 조용히 장부에 들어가는 일이 늘지 않는다.

| 단계 | 지금 | AI를 넣은 뒤 |
|---|---|---|
| 읽기 | 사람이 서류를 보며 한 줄씩 읽음 | **AI**가 PDF에서 거래처, 날짜, 품목, 수량, 단가, 합계를 추출 |
| 검산 | 사람 눈 | 수량×단가=금액, 품목 합=합계(세액 포함), 글자 인식 신뢰도로 **자동 검산**, 이상하면 "확인 필요" |
| 확인 | 모든 값을 입력하며 확인 | 사람은 **확인 필요 값만** 원본과 박스 위치를 보며 확인 |
| 반영 | 입력 즉시 장부에 | **사람이 확인한 뒤** 장부에 반영 |

- 선택한 모델과 이유: PaddleOCR PP-OCRv5 한국어. 글자마다 **박스와 신뢰도**를 주기 때문에 "확인 필요" 판정과 위치 안내를 만들 수 있고, 노트북 CPU에서 장당 약 17초로 돕니다. 후보 비교와 라이선스 확인은 [03_후보표.md](03_후보표.md), 결과는 [05_결과비교.md](05_결과비교.md).
- **AI는 초안만 만들고 반영은 사람이 합니다.** 금액·수량 오류가 손해로 이어지고 되돌리기 어렵기 때문입니다. 결과물은 **엑셀 행 초안**입니다. 확인 필요 행은 노란색으로 사유와 원본 위치가 붙고, 사람이 확인한 뒤 "확인 완료" 칸에 표시합니다(`examples/ledger_A_test20.xlsx`).
- **자료는 외부로 보내지 않습니다.** 거래처명과 단가가 들어 있습니다. 그래서 외부 OCR·LLM 서비스는 처음부터 후보에서 뺐습니다.

## 4. 대상 사용자
- **주 사용자**: 가게에서 명세서를 장부에 입력하는 사람(사장, 직원).
- **가장 도움받는 상황(가정)**: 명세서를 여러 장 입력해야 하는 날. 이 가게의 실제 상황은 확인하지 못했습니다.
- 이 PoC의 사용자는 "확인 필요 값을 검토하는 사람"이며, AI가 장부를 직접 고치지는 않습니다.

## 5. 성공 기준
모델을 돌리기 전에 고정했고 결과를 본 뒤 바꾸지 않았습니다. 숫자는 현행 수준을 재지 않아 노트북 예시 기준을 빌렸습니다.

| # | 기준 | 목표 | 현재 상태 (합성 시험용 20장) |
|---|---|---|---|
| 1 | 품목의 조용한 오류(틀렸는데 확인 필요 표시도 없음) | 102개 중 3개 이하 | **0** 달성 |
| 2 | 거래처·날짜·합계의 조용한 오류 | 60개 중 1개 이하 | **0** 달성 |
| 3 | "확인 필요"로 넘긴 비율 | 20% 이하 | **18.5%** 달성(여유 적음) |
| 4 | 합계 불일치 표시(20번만 원본 오류) | 20장 모두 맞게 | **20/20** 달성 |
| 5 | 값마다 원본 위치 | 전 항목 | **100%** 달성(형식 기준. 기울어진 스캔에서는 박스가 옆 줄까지 덮음) |
| 6 | 처리 시간 | 장당 평균 60초 이하(잠정) | **16.6초** 달성 |
| 7 | **수기 입력 대비 시간 단축**: AI 보조 검토 시간(AI 처리 시간 포함)의 중앙값이 수기 입력의 몇 % 이하이고, AI 보조의 최종 틀린 칸이 수기보다 늘지 않는다 | **재기 전에 정해서 적는다: ___% 이하** ([측정 절차](07_수기입력_측정절차.md)) | **미검증** (측정 도구는 준비됨, 아직 재지 않음) |

- 기준 1~6은 **PoC가 동작하는지**, 기준 7은 **실제로 나아지는지**를 봅니다. 가설의 ①(시간 단축)은 기준 7을 재기 전에는 증명되지 않았습니다.
- 기준 3은 "전부 확인 필요로 넘기는" 꼼수를 막습니다. 기준 1·2는 틀렸어도 확인 필요로 넘겼다면 사람이 잡을 수 있으므로 세지 않습니다.
- 어려운 사례(손글씨 정정, 기울어진 저화질, 복잡한 양식, 합계 불일치)를 시험용 20장 중 4장에 넣었습니다.

## 6. 범위와 가정
- **범위 안**: 명세서 PDF 한 장에서 위 6개 값을 뽑아 확인 필요 표시와 위치를 붙이는 것.
- **범위 밖**: 장부 프로그램 자동 반영, 세금계산서 전자 발행 연동, 고객 문의 응대, 카톡 발주 정리.
- **데이터**: 실제 명세서가 아니라 **합성 샘플**로 쟀습니다(개인·거래 정보를 쓰지 않기로 해서). 합성 샘플은 실제 서류의 번짐과 거래처별 양식 차이를 다 재현하지 못합니다.
- **작성 중 가정**: 사장·직원이 명세서를 입력한다는 점은 인터뷰 답("사장이랑 직원")에 근거합니다. 거래처 수, 명세서 건수, 현재 사용하는 장부 프로그램은 확인하지 못했습니다.
