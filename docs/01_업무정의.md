# 0단계 · 업무 정의

작성일: 2026-11-17

## 업무
식당(이자카야)에 거래처(식자재·주류 납품처)에서 오는 거래명세서를 보고, 사장이나 직원이 장부(엑셀)에 거래처, 날짜, 품목, 수량, 단가, 합계를 옮겨 적는다. (실제 거래처 수는 확인하지 못했다. 합성 샘플에는 가상의 거래처 6곳을 썼다: 닭, 채소, 수산, 정육, 면·가공품, 주류)

## 업무 유형
**입력과 전사.** 판단은 거의 없고 옮겨 적는 작업만 있다.

## 병목
- 옮겨 적는 데 시간이 든다(거래처 쪽에서 손이 가장 많이 가는 일로 꼽음). 실제 업무의 장당 시간은 재지 못했고, 합성 서류 8장을 한 사람이 입력한 값만 있다(docs/08_측정결과.md).
- 옮겨 적은 값이 그럴듯하면 검산 없이 넘어간다. 틀려도 알아채기 어렵다.

## 지금 처리 방식 (기준선)
사장과 직원이 명세서를 보며 직접 입력한다.
- 현행 수준(장당 입력 시간, 오류율)은 **측정하지 않음**. → 제약으로 기록.

## 틀렸을 때
- 금액·수량 오류가 정산과 발주에 그대로 이어져 손해가 난다.
- 그래서 AI는 **엑셀 행 초안만 만들고, 반영은 사람이 확인한 뒤 한다.** 신뢰도가 낮은 값과 합계가 맞지 않는 문서는 "확인 필요"로 넘긴다.

## 적용하지 않을 업무 3조건 점검

| 조건 | 판정 | 근거 |
|---|---|---|
| 판정 기준이 사람마다 다른가 | 통과 | 서류에 적힌 값을 그대로 옮기는 일이라 정답이 하나다 |
| 틀렸을 때 되돌릴 수 없는가 | 통과(조건부) | 사람이 확인 후 반영하고, 합계 교차검산으로 오류를 잡는다 |
| 판정 기록이 없는가 | **제약** | 실제 입력 기록을 쓰지 않기로 함. 합성 샘플 20장을 만들고 정답을 생성 시점에 함께 저장했다 |

## 자료와 실행 조건
- 실제 명세서에는 거래처명과 단가가 있으므로 **외부 반출 불가로 가정**한다. 외부 API 후보는 제외.
- 실행 환경: 노트북 GPU (NVIDIA RTX 4050 Laptop, VRAM 6GB, nvidia-smi로 2026-11-17 확인).
- 테스트 자료: `sample-invoices/` 합성 스캔 PDF 20장(쉬움 16, 어려움 4), 품목 102줄.

## 제약 (결론에 반드시 남길 것)
1. 성공 기준을 정할 때는 현행 수준 미측정 → 숫자는 노트북 예시 기준을 빌려 썼다. 이후 합성 서류 8장의 수기 입력 시간을 한 사람이 쟀다(docs/08_측정결과.md).
2. 합성 샘플로만 잰다 → 구축 결정 전에 실제 서류 5~10장(거래처명·단가 가림)으로 다시 잰다.
3. 합성 샘플은 실제 서류의 번짐, 거래처별 양식 차이를 다 재현하지 못한다.
