# 수기 입력 대비 측정 절차 (기준 7)

목적: "AI 보조 검토가 수기 입력보다 낫다"를 같은 서류, 같은 사람으로 확인합니다.
가장 쉬운 방법은 **측정 앱**입니다(브라우저에서 클릭만으로 재고 결과 계산까지). 명령줄 도구([src/measure.py](../src/measure.py))는 아래 "앱 없이 재기"에 있습니다.

## 측정 앱으로 재기

```bash
python -X utf8 -W ignore src/measure_app.py
```

브라우저가 열립니다(안 열리면 `http://127.0.0.1:8765/`). 이 컴퓨터 안에서만 돌고 자료는 밖으로 나가지 않으며, 새로 설치할 패키지는 없습니다. 끝내려면 터미널에서 Ctrl+C를 누릅니다. 결과는 `measurement/` 폴더에 쌓입니다.

### 1. 처음에 두 가지를 정합니다
- **측정자**: 한 사람이 끝까지 재야 비교가 맞습니다. 별명도 됩니다(결과 파일에 그대로 적히고 저장소에 올리면 공개됩니다).
- **목표 시간 비율**: AI 보조 시간의 중앙값 ÷ 수기 시간의 중앙값이 이 값 이하이면 목표 달성입니다(예: 0.7). 숫자는 직접 정하세요. **첫 측정을 마치면 바꿀 수 없습니다.** 결과를 보고 목표를 바꾸지 못하게 하려는 장치입니다. 오류 조건(AI 보조의 틀린 칸이 수기보다 늘지 않음)은 항상 같이 적용됩니다.

### 2. 연습을 먼저 합니다
홈 화면의 "수기 입력 연습", "AI 보조 연습"으로 화면에 익숙해집니다. 연습한 시간과 값은 저장되지 않습니다.

### 3. 일차별로 합니다
서류 8장을 두 조로 나눴습니다. 서류의 줄 수와 양식이 두 조에 고르게 섞이고, 어려운 서류(18번, 19번)는 조마다 하나입니다.

| | X조 (01, 02, 05, 19) | Y조 (08, 11, 14, 18) |
|---|---|---|
| **1일차** | 수기 입력 | AI 보조 |
| **2일차** | AI 보조 | 수기 입력 |

- 모든 서류를 두 방식으로 재면서도 같은 서류의 두 측정 사이에 하루가 생기고, 두 방식 중 어느 쪽이 먼저인지도 반반입니다(서류를 기억하는 효과와 순서 효과를 줄이려는 설계).
- 1일차와 2일차는 **하루 이상** 띄우세요. 12시간이 안 지났으면 앱이 경고하고, 그래도 하면 간격이 기록에 남습니다.

### 4. 서류마다 이렇게 합니다
1. 목록에서 **시작**을 누릅니다. 안내를 읽고 다시 **시작**을 누르면 서류와 입력 칸이 같이 나오고 타이머가 돕니다(읽는 시간이 시간 밖으로 빠지지 않습니다).
2. **수기 입력**: 서류를 보면서 거래처, 날짜, 모든 품목 줄을 직접 입력합니다. 합계는 입력하지 않지만 서류와 맞는지 눈으로 확인합니다.
3. **AI 보조**: AI가 만든 초안이 채워져 있습니다. **노란색 행과 칸만** 서류와 대조해 고칩니다. 회색(잠김)은 고칠 수 없고(서버도 막습니다) 보지 않는 것이 약속입니다. 잘못 만들어진 노란 줄은 삭제할 수 있고, 노란색이 하나도 없으면 바로 완료합니다.
4. 전화나 손님 때문에 끊기면 **일시정지**를 누릅니다(정지 중에는 서류가 가려집니다). 실수로 새로고침해도 일시정지 상태로 이어집니다.
5. **완료**를 두 번 누르면(두 번째가 확정) 저장되고 목록으로 돌아갑니다. 틀리게 했으면 "다시 하기"로 다시 할 수 있고 기록에 "다시 측정함"이 남습니다.

### 5. 결과를 봅니다
홈 화면 아래의 **결과 계산**을 누릅니다. 수기와 AI 보조를 둘 다 마친 서류가 한 장 이상 있어야 계산되고, 8장을 모두 마친 뒤에 보는 것을 권합니다.
- 시간 중앙값(AI 보조는 사람이 검토한 시간 + AI 처리 시간 약 17초), 단축 비율, 목표 판정
- 틀린 칸 수와 그중 **조용한 오류**(노란색이 아닌데 틀림), 서류별 표, 한계
- 결과는 `measurement/result_<시각>.md`로 저장됩니다. 기록이 쌓이는 파일: `timing_log.csv`, `manual_entries.csv`, `assisted_final.csv`, `state.json`.
- 끝나면 그 숫자를 `docs/00_문제정의서.md`의 기준 7과 README에 옮깁니다.

## 앱 없이 재기 (명령줄)
```bash
python -X utf8 src/measure.py template --out measurement
```
`timing_log.csv`(기록 시트)와 `manual_entries.xlsx`(수기 입력용 빈 시트)가 만들어집니다. 스톱워치로 직접 재서 `timing_log.csv`에 초를 적고, AI 보조용은 `examples/ledger_A_test20.xlsx`를 `assisted_final.xlsx`로 복사해 노란 행만 고칩니다. 계산:
```bash
python -X utf8 src/measure.py report --timing measurement/timing_log.csv --manual measurement/manual_entries.xlsx --assisted measurement/assisted_final.xlsx --target-time-ratio 0.7 --out measurement/result.md
```
`--target-time-ratio`는 재기 전에 정한 숫자로 바꿉니다. 앱이 만든 `.csv` 파일도 같은 방식으로 넣을 수 있습니다.

## 규칙 요약
- **틀린 칸**: 서류마다 거래처·날짜 2칸 + 품목마다 품목·수량·단가·금액 4칸 중 정답과 다른 칸. 빠뜨린 줄은 4칸 모두, 정답에 없는 줄을 넣으면 그 줄의 4칸이 틀린 것으로 셉니다.
- **조용한 오류**: 틀린 칸이 있는데 그 행의 "확인 필요"가 비어 있는 경우. 빠뜨린 줄은 표시할 행이 없어 조용한 오류로 셉니다.
- **목표 달성**: 시간 목표와 오류 조건을 **둘 다** 만족할 때만.
- 정답 파일(`sample-invoices/정답*`)은 재는 동안 열지 않습니다.

## 이 측정으로 말할 수 있는 것과 없는 것
- 말할 수 있는 것: 이 사람이 이 합성 서류 8장에서 수기와 AI 보조의 시간·오류를 비교한 결과.
- 말할 수 없는 것: 다른 사람이나 실제 서류, 하루 업무량으로의 일반화.
- AI 초안은 이 서류들에 이미 한 번 돌려서 얻은 결과입니다(파서는 개발용 샘플로만 다듬음). 그래서 이 측정은 **새 서류에서의 성능**을 보여 주지 않습니다. 반대로 "노란색 행만 본다"는 약속은 현실의 습관보다 엄격해서, 실제로는 눈에 띄는 오류를 고치게 되어 오류가 더 줄 수도 있습니다.
- 앱의 서류는 모니터에 띄운 합성 이미지입니다. 종이를 보며 입력하는 실제 업무와 다릅니다.
- 더 강한 증거가 필요하면 거래처명·단가를 가린 실제 명세서 5장으로 같은 절차를 반복합니다(실제 서류와 정답은 저장소에 올리지 않고 결과 숫자만 올립니다).
